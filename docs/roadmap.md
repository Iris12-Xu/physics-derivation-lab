# 开发路线

> 状态：MVP 范围已确定；MVP 后的精确顺序可根据实现证据调整。

## 路线原则

- 先完成最小可靠闭环，再扩大物理范围；
- 先证明正确性和可追踪性，再做性能优化；
- 先使用结构化输入，再增加 AI 自然语言前端；
- 每个里程碑都要有可运行案例和自动验证；
- 新能力不能削弱知识来源、适用条件和失败边界。

## Milestone -1：需求与价值验证基线

在大量架构实现之前，先建立一组冻结的光学问题和参考答案，用来验证项目解决的是否是真实问题，而不只是完成技术闭环。

第一阶段先完成：

- 收集 10～20 个探索性案例，并逐步扩展为参数化问题族；
- 覆盖角度约定、单位混用、数学分支、全反射、能流因子、近似越界、色散范围和条件缺失；
- 为每个案例建立经过复核的参考答案、适用条件和错误变体；
- 冻结一部分未参与实现设计的保留测试；
- 记录通用 AI 单次回答、AI 自检和 AI 使用 Python / SymPy 后的结果；
- 保存模型、版本、提示词、工具和运行时间，保证基线可解释。

工程 MVP 完成后，再用同一批冻结问题比较 Physics Derivation Lab。重点指标包括：

- 支持范围内的正确率；
- 错误接受率与正确拒绝率；
- 物理解筛选正确率；
- 条件不足时的拒绝质量；
- 独立验证证据完整率；
- 相同输入的可复现性；
- 生成代码与参考实现的一致性；
- 运行成本、延迟和人工复核时间。

这一阶段验证产品假设，不扩大 Milestone 1 的工程范围。如果结果不能证明确定性、可追溯性或正确拒绝带来实际增益，应调整支持范围、目标用户或项目定位。

## Milestone 0：项目与最小 Physics IR

目标：

- 建立 Python 项目和测试骨架；
- 定义最小任务、物理量、定律、约束、模型和结果结构；
- 实现安全表达式解析；
- 建立最小几何光学知识目录。

完成条件：

- 示例 YAML 可以解析为内部模型；
- 非法符号、函数和结构能被拒绝；
- 斯涅耳定律知识条目带有来源、条件和审核状态；
- 基础单元测试通过。

## Milestone 1：MVP——斯涅耳定律闭环

固定流程：

```text
YAML
  → Physics IR 校验
  → 审核知识关系检索
  → 确定性推导计划
  → SymPy 执行
  → 分支分类
  → 验证报告
  → NumPy + pytest
```

完成条件以根目录 README 的 MVP 验收清单为准。

MVP 不要求：

- AI；
- Web；
- C++ / CUDA；
- 彩虹案例；
- 完整 Numerical IR；
- 通用动态推导；
- 其他物理领域。

## Milestone 2：彩虹综合案例

目标：

- 建立球形水滴模型；
- 支持一级彩虹，并为二级或一般 \(p\) 次内部反射保留扩展空间；
- 表达偏向角和驻点条件；
- 引入折射率色散；
- 对照独立数值求根；
- 视可用数据与 Opticks 或其他可信结果交叉验证。

此阶段用于检验多关系组合、几何模型、分支和复杂验证，不属于 MVP。

## 几何光学扩展清单

以下内容属于 MVP 后的领域清单，尚未冻结为严格的里程碑顺序。

### 基础界面光学

- 反射定律；
- 临界角与全反射；
- 布儒斯特角；
- S、P 偏振的菲涅耳系数；
- 强度反射率和能流透射率；
- 能量守恒检查。

菲涅耳关系不能只由斯涅耳定律推出，还需要相应的电磁场边界条件。知识库必须准确表达这一依赖，不能因为两个公式属于同一场景就省略推导来源。

### 几何成像与光线传播

- 球面折射；
- 薄透镜与透镜制造者公式；
- 傍轴近似；
- ABCD 矩阵；
- 多透镜系统；
- 完整球面光线追迹。

### 彩虹与色散

- 球形水滴模型；
- 折射率随波长变化；
- 一级、二级和一般 \(p\) 次内部反射；
- 偏向角与驻点条件；
- 偏振强度；
- 光线路径可视化；
- 与独立模拟结果对照。

具体实现顺序由知识依赖、验证难度和对架构的检验价值共同决定。

## Milestone 3：Numerical IR 与多后端

目标：

- 建立数值表达式图；
- 公共子表达式消除；
- 常量折叠；
- 显式分支处理；
- 数值稳定形式替换；
- NumPy 向量化；
- C++ 后端；
- 基准测试。

CUDA 只有在 CPU/NumPy 基准和目标工作负载证明需要后再启动。

## Milestone 4：Web 界面

目标：

- 结构化问题表单；
- 模型与条件确认；
- 推导轨迹展示；
- 数学解分类；
- 参数控制和绘图；
- 代码与验证报告导出。

Web 只调用核心 API，不能复制或绕开核心验证逻辑。

## Milestone 5：可选 AI 前端

目标：

- 自然语言映射为待确认的 Physics IR；
- 发现缺失条件；
- 每次询问一个关键问题；
- 推荐知识库中已有的关系；
- 解释推导、验证和错误。

AI 输出不能直接进入可靠知识库，也不能成为推导正确性的证据。

## Milestone 6：扩展领域

候选方向：

- 经典力学；
- 振动与波；
- 电磁学；
- 数学物理方法；
- 量子力学。

每个新领域必须先定义：

- 最小知识范围；
- 规范变量和模型；
- 代表性闭环案例；
- 分支与验证规则；
- 明确的不支持边界。

## 里程碑调整规则

允许调整：

- MVP 后里程碑的精确顺序；
- 实现模块和依赖；
- 某项能力拆分或合并的方式。

不允许因进度压力而弱化：

- 知识来源与审核状态；
- 模型假设的显式表达；
- 数学解与物理解区分；
- 验证分级；
- 知识不足时停止的行为。
